# ボーカル・ピッチエディタ

アカペラ音声の**音程を、歌い方を壊さずに直す**ための Web アプリ。
Melodyne / Auto-Tune Graph Mode に相当する編集を、ブラウザ上のピアノロールで行う。

WORLD ボコーダーで **F0（基本周波数）だけを差し替えて**再合成するため、声質（フォルマント）は元のまま保たれ、
音程を大きく動かしても声が変わらない。編集の境界にクリックノイズが出ないことも原理的に保証される。

---

## できること

### 1. 音程を直す

読み込んだ音声は自動で音符に区切られ、青いバーとしてピアノロールに並ぶ。
バーを上下にドラッグすれば音程が変わる。白い曲線が実際の音程の動きを表す。

- **50 セント単位でスナップ**（半音の半分）。`Shift` で 1 セント、`Alt` で 100 セント刻みに切り替わる。
- 1 つのバーを**任意の位置で分割**でき、前半と後半で別々の音程にできる。
  境界は S 字補間で滑らかにつながるため、音が途切れない。分割線をドラッグすれば位置を、
  `Ctrl` を押しながらなら**つながり方の速さ（遷移区間）**を調整できる。
- **補正の強さ**（0〜1）で、原音のビブラートやしゃくりをどれだけ残すかを決める。
  0 なら歌い方はそのままに音程だけ平行移動、1 なら目標音程に完全に貼り付く。
  選択したバーに対して効くので、バーを選ぶと操作できるようになる。

### 2. 録音する・重ねる

マイクから直接録音でき、そのまま編集対象になる。録音は**通話向けの前処理（自動音量調整・ノイズ抑制・
エコーキャンセル）をすべて無効化**した生の PCM で取り込む。これらが有効だと音量やスペクトルが勝手に加工され、
音程解析と音量編集が成立しなくなるため。

- 録音ボタンを押すたびに**新しいトラックが増える**。既存の音声を聴きながら重ねて録れる。
- ヘッダーの **Tracks** で、どのトラックを鳴らすかを個別に切り替えられる。
  トラックごとに色が決まっていて、ピアノロールのバーの色と一致する。
- 各トラックの **×** で削除でき、削除は `Cmd/Ctrl+Z` で元に戻せる。
- 録音前に**レベルメーター**でピークを確認できる。**メトロノーム**（BPM・拍子指定）付き。
  設定したテンポは、そのまま編集画面の小節線として表示される。

### 3. 音を仕上げる

| | 内容 |
|---|---|
| **バー単位の音量 / ミュート** | 区間ごとの音量。境界は dB 領域で滑らかに補間されるため段差が出ない |
| **ハモリ** | バーをコピーして別の音程に貼れば、元と同時に鳴る別声部になる |
| **ノイズ低減** | 声の合間のサーというノイズを 0〜−40 dB の範囲で下げる。閾値は素材から自動推定 |
| **ディレイ** | Time / Feedback / Mix。短い Time は厚み、長い Time は山びこになる |
| **リバーブ** | プリディレイ・初期反射・周波数別減衰を持つ残響。元の声を減らさず足すセンド方式 |
| **マスター音量** | 出力全体。最終段のトゥルーピーク・リミッターが −1 dBTP を守る |
| **伴奏トラック** | 伴奏を読み込んでアカペラと同時再生（音量・ミュート・ソロ・頭合わせ） |

### 4. 書き出す

WAV / FLAC / MP3 で保存できる。ボーカルのみ／伴奏込みミックスを選べる。
**書き出しはプレビュー再生とまったく同じ処理経路**を通るので、聴いた音とファイルの音が食い違わない。

編集状態だけを JSON で保存することもできる。音声ファイルと JSON があれば編集を完全に復元できる。

## 画面の操作

| 操作 | 挙動 |
|---|---|
| バーを縦ドラッグ | 音程（`Shift`=1 セント / `Alt`=100 セント） |
| `S` | カーソル位置で分割 |
| 分割線ダブルクリック | 結合 |
| 分割線ドラッグ | 分割位置 / `Ctrl` 併用で遷移区間長 |
| `G`+縦ドラッグ | バーの音量 |
| `M` | ミュート切替 |
| 空き領域をドラッグ | 範囲選択（複数バーを一括操作） |
| `A`+クリック | 選択に追加 |
| `Cmd/Ctrl+C` → カーソルを置いて `V` | ハモリを任意の音程に複製 |
| `Delete` | ハモリを削除 |
| `Cmd/Ctrl+Z` / `Shift+Z` | アンドゥ / リドゥ |
| ホイール | 上下スクロール（`Shift` 併用で左右） |
| `Cmd/Ctrl`+ホイール | 時間軸ズーム（`Shift` 併用で音程軸） |
| Zoom の `↔` `↕` | 時間軸 / 音程軸のズーム |

- **ドラッグ中に画面端へ寄せると自動でスクロール**する。画面外に 1 秒以上出したままにすると加速する。
  再生ヘッドのドラッグ、範囲選択、音程バーの移動のいずれでも効く。
- **再生中は編集がロックされる。** 再合成は全区間を一括で行う方式のため、再生中の差し替えを許すと
  位相の不連続＝クリックノイズが原理的に避けられなくなる。
- 縦軸（音程）は **C2〜C6 に固定**。読み込み直後は収録された音域が画面いっぱいに見えるよう自動で合わせる。
  軸が固定なので、バーを動かしても目盛りが伸縮せず、画面外に消えない。
- 操作ガイドはヘッダー右下のボタンで開閉できる。

## セットアップ

**Python 3.9 以上**があれば、リポジトリ直下で 2 ステップ。

```bash
./setup.sh        # 初回のみ: .venv を作り依存を pip で入れる（数分）
./start.command   # 起動: サーバー → ブラウザ(http://localhost:8000/) が開く
```

- macOS では Finder で **`start.command` をダブルクリック**するだけでもよい（`.venv` が無ければ自動でセットアップ）。
- 停止は `./stop.command`。PID ファイル経由で止め、取りこぼした場合はポート 8000 を掴んでいるプロセスを探して止める。
- Windows / Linux は `.command` の代わりに:
  ```bash
  source .venv/bin/activate && cd server && uvicorn app:app --port 8000
  ```
- マイク録音は HTTPS でないと権限が降りないが、`localhost` は例外として許可される。
- `pyworld` は多くの環境でビルド済み wheel が入る（ソースビルドになる場合のみ Xcode CLT / build-essential が必要）。
  `pyworld` は実行時に `pkg_resources` を参照するため、`setuptools<81` を固定している。

## 設計原則

この 4 つを守ることで、本アプリの難所（分割しても音が途切れない・クリックが出ない）はすべて解決する。
逆に破ると後から取り返しがつかない。

| # | 原則 | 理由 |
|---|---|---|
| **P1** | 音声波形は一切切らない。編集対象は F0 曲線とゲイン包絡のみ | 波形を切って繋ぐ実装は境界でクリックノイズが必ず出る |
| **P2** | 再合成は全区間を一括で行う | ボコーダーが位相を連続生成するため、クリックが原理的に発生しない |
| **P3** | 編集は非破壊。操作は「元 F0 への変換パラメータ」として保持する | 何度でも再編集・リセットできる |
| **P4** | 音声の実体はサーバー側に置き、クライアントとは JSON だけをやり取りする | 解析データ（`sp`/`ap`）は原音の約 10 倍のサイズになる |

「ノートの分割」とは音声を分割することではなく、**F0 曲線に対する編集パラメータの適用区間を分割する**ことである。
波形は最後まで一本のまま扱われる。

## アーキテクチャ

```
ブラウザ (server/static/)                    サーバー (server/)
  Canvas 2D ピアノロール                       FastAPI
  Web Audio 再生 / AudioWorklet 録音           WORLD (pyworld) 解析・再合成
        │                                            │
        │  POST /api/session  ── 音声 ──────────────▶ │ 無音でフレーズ分割 → 各フレーズを解析
        │  ◀── f0 / rms / ノート（sp・ap は送らない）─ │ sp / ap はメモリ常駐
        │                                            │
        │  POST /api/render   ── EditState(JSON) ───▶ │ 再合成して WAV を返す
        │  POST /api/export   ── EditState(JSON) ───▶ │ フル解像度で書き出し
```

### 信号チェーン

順序には理由がある。**バー単位の音量は必ず空間系より前**（後ろに置くと、小さくしたはずの音の残響だけが
元の音量で残る）。**マスターゲインは空間系より後**（残響量を変えずに全体音量だけ変えたい）。
**ノイズ低減も空間系より前**（後ろに置くとノイズに残響が掛かってかえって目立つ）。

```
原音 → WORLD 分析 (f0, sp, ap)
     → renderF0()        F0 曲線を編集後の値に差し替え
     → pw.synthesize()   全区間を一括で 1 回だけ
     → renderGain()      バー単位のゲイン包絡（dB 領域で smoothstep 補間）
     → ノイズ低減        下方伸張（閾値は素材から自動推定）
     → ディレイ          Time / Feedback / Mix
     → リバーブ          プリディレイ + 初期反射 + 周波数別減衰
     → マスターゲイン
     → トゥルーピーク・リミッター（−1 dBTP）
     → 出力
```

`renderF0()` と `renderGain()` は同じ smoothstep 補間ヘルパを共有する。
「セグメント配列 + 遷移長 → フレーム単位の連続曲線」を 1 つの関数で作ることで、
ピッチだけ滑らかでゲインがガタつく、という不整合が起きない。

### 音質面の実装

- **選択的再合成** — WORLD を通すと僅かに質感が変わるため、**実際にピッチ編集した区間だけ**を合成音にし、
  それ以外は原音 PCM を使う（Hann 平滑したゲートでブレンド。ゲート端では両者の音高が一致するので繋ぎ目が出ない）。
  音量だけの編集ならボコーダーを通さず、無編集のフレーズは原音をそのまま返す（ビット一致）。
- **フレーズ分割** — 完全な無音（RMS < −50 dB が 150 ms 以上）でのみ音声を分割し、各フレーズを独立に解析・
  キャッシュする。有声区間の途中で切らない限り連結は安全で、長尺でも `sp`/`ap` のメモリが破綻しない。
- **ルックアヘッド・リミッター** — 64 サンプル単位のブロックゲインに 6 ブロックの先読みと
  0.5 dB/ブロックのリリース制限を掛ける。信号全体を一律に下げる実装だと、マスターを上げても
  同じだけ下げられて打ち消されてしまう。
- **リバーブ** — 指数減衰させた白色雑音をそのまま畳み込むと「箱の中」のように籠る。
  プリディレイ 22 ms・不等間隔の初期反射 9 個・高域ほど速い減衰・残響側の低域カット（190 Hz / 24 dB/oct）で
  実際の部屋の応答に近づけている。
- **ディレイ** — 短い遅延ほど遅延時間をゆっくり揺らす。短い固定遅延を原音に足すと周波数軸に等間隔の谷
  （コムフィルタ）ができて金属的に色付くため、谷の位置を動かして散らす。効きは 40 ms 以下で最大、
  120 ms 以上でゼロへ連続的に変わるので、どこにも音が急変する境目がない。
- **ノイズ低減** — 閾値をノイズフロア推定（下位パーセンタイル）から自動で決め、つまみは減衰量だけを変える。
  ゲイン曲線は 30 ms 幅で平滑化してから掛ける（急に開閉すると息継ぎの前後が不自然に途切れる）。

### 描画の実装

- **キャンバスは表示範囲ぶんだけ確保する。** スクロール範囲は空の div が作り、キャンバスは transform で
  スクロール位置に貼り付く。内容全体ぶんのキャンバスを持つ実装だと、ズーム 3〜4 段で 1 GB 級の
  ビットマップ確保が走って操作が固まる。この方式ならズーム率に依らずメモリは一定（約 33 MB）。
- 描画は**見えている範囲だけ**に絞る（行背景・小節線・F0 曲線・バーのいずれも範囲外はスキップ）。
- 座標変換（`time↔x` / `cents↔y`）は 1 箇所に集約している。ここが散らばるとズーム・スクロールで破綻する。
- ズームは横 12000 px/秒・縦 600 px/半音まで。どちらも画面中央の位置を保ったままスケールする。
- 開発中に HTML / CSS / JS が別々にキャッシュされると分かりにくい壊れ方をするため、
  サーバーは `/` と `/static/` に `Cache-Control: no-cache` を付ける（ETag 検証なので転送量は増えない）。
  UI の骨格（スクロール用の div や overflow 指定）は JS 側でも組み立てるので、古い HTML/CSS が
  残っていても動作する。

python -m pytest tests/ -q      # 35 件（受け入れ基準 AC-1〜21、リミッター、選択的再合成 ほか）

## アプリケーション化について

現状は「ローカルで起動して使う」形。配布したい場合の選択肢:

- **デスクトップアプリ化** — PyInstaller で `.app`/`.exe` に固める、または Electron / Tauri + Python 同梱。
  利用者は Python を意識せず起動できる。
- **Web サービス化** — サーバーにデプロイし、URL で誰でも利用（Python はサーバー側で動く）。
- **完全ブラウザ単体** — WORLD を WebAssembly へ移植すれば Python 不要になるが、大掛かり。

いずれも音声エンジンが WORLD（C/Python）である点は共通で、Python を「隠す」ことはできても、
WASM 化以外で完全に無くすことはできない。
